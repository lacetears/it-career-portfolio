## Improvements and specific defects

### Help desk

- Non-ASCII CSRF token previously caused TypeError instead of a controlled rejection; compare encoded bytes and test a 400 response.
- Add constrained categories and idempotent migration preserving legacy tickets/notes; create queue/history indexes and relationship triggers for old databases.
- Add category/priority/assignee filters, 25-row pagination, retained filter links and validation for query parameters.
- Add readable 400/404/413 pages and configurable database path; retain the existing creation, assignment, statuses, work notes and history.
- Extend tests to category assignment/history, field limits, body limits, headers and old-schema migration.

### Sales

- Fix stale real-data dashboard: regenerate it from report JSON/template, use current period/quality counts and show exact pence.
- Reconcile cleaned-source signed sums, SQL totals, monthly-country groups and retained/excluded row counts.
- Fix malformed-row and empty-workbook failures; close workbooks on errors and support isolated output directories.
- Reject out-of-range monetary values before dashboard integer precision is lost; retain signed credits and half-up rounding.
- Fix synthetic CSV missing-field crashes, distinguish conflicting IDs from duplicates, normalize dates before SQL grouping and handle no completed orders.
- Add fresh XLSX integration tests, deterministic-output checks, safe-embedding checks, generated-retail-script tests and a stale-dashboard CI check.

### Security analyzer

- Validate object shape, required field types, nonempty identities, IP addresses, timezone-aware timestamps and integer configuration.
- Normalize UTC/IP representations; suppress exact normalized duplicates by default with an override for coarse timestamp sources.
- Add same-host/IP multi-user spray correlation with a labeled synthetic fixture and separate suppression state.
- Expose thresholds/window, explicit IP exclusions and strict-or-skip-invalid JSONL parsing with line diagnostics.
- Prevent overwriting input with output and return actionable CLI errors. Preserve the original two alert rules and eight-event fixture behavior.

### Presentation and maintenance

Rewrite the three root READMEs around actual commands, architecture, tradeoffs, tests and limits. Add security notes and two-version CI. Clarify the hub's legacy code and browser-only demos, refresh its sales page and include a profile README draft, recruiter role mapping, nine neutral resume bullets, three LinkedIn drafts and 15 interview questions/answers.

## Limitations and remaining work

- Help desk remains localhost-only without authentication, authorization, verified actor identities, SLAs or concurrent-edit protection. Migration preserves existing orphans rather than silently deleting them.
- Detection rules are synthetic batch demonstrations. No real SIEM deployment, native event adapter, accuracy benchmark, distributed-attack detection or throughput claim.
- The sales duplicate-removal policy is an assumption. Memory use grows with source size. No verified PBIX, warehouse deployment or predictive model.
- Dashboard tests use a minimal DOM; no new visual browser, accessibility, load or penetration testing was performed. Existing screenshots show earlier browser demos and are labeled accordingly.
- Source review and a targeted secret-pattern scan are not comprehensive vulnerability scanning. Do not publish real logs, ticket content, customer IDs or credentials.
- The old combined implementations remain for continuity and may lack newer fixes; their warnings point to the maintained projects. Removing them requires a separate owner decision.
- The profile draft is not installed on the profile; there was no profile README repository. Pins were recommended, not changed. No PR is merged automatically, and published GitHub Pages will remain unchanged until the hub PR is merged/deployed.
